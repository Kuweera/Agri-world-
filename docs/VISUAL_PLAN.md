# AgriWorld 3D - Visual Plan (textured, multi-stage, mobile-friendly)

Goal: crops, tractor and land that look like real farming, with distinct growth stages,
inside mobile budgets. Offline gameplay and saves are NOT changed by this plan.

## 1. Architecture check (what exists today)

Ready:
- Save file stores crop id + planted_at + tile state, never looks. Visuals can change freely.
- Growth is a time-based progress 0..1 computed in game_state.gd. The view only displays it.
- farm_grid.gd already caches meshes per (crop, stage) and swaps meshes only on stage change.

Gaps to close in V1:
1. Stage thresholds are hard-coded (crop_models.gd: 0.34 / 1.0) and there are only 3 stages.
2. crop_data.gd holds economy + one colour. No visual data. A new crop means editing code.
3. mesh_builder.gd has no UVs, so nothing can be textured yet.
4. No assets folder, no licence record, no size checks in CI.
5. Sky/light/shadow setup lives inside farm_main.gd (should be one environment script).
6. Mesh memory grows with crops x stages x variants x detail. Needs lazy building and a budget.

## 2. Target data model (crop_data.gd, V1)

Each crop gets a visual block, for example:
  "visual": {
    "archetype": "cereal",            # cereal, legume_bush, tuber, tree_crop ...
    "stages": [                       # from = progress where the stage starts
      {"name": "sprout",     "from": 0.00},
      {"name": "vegetative", "from": 0.30},
      {"name": "mature",     "from": 0.65},   # tassel / flowers / pods forming
      {"name": "ripe",       "from": 1.00},
    ],
    "plants_per_tile": 4,
    "atlas": {"leaf": "maize_leaf", "fruit": "maize_cob"},   # named regions in the atlas
  }
A pure crop_stages.gd turns (crop_id, progress) into a stage index, with headless tests.
Later logic (water, fertiliser, pests, weather) can add stage variants ("wilted") without touching saves.

## 3. Rendering plan

- One environment_setup.gd: sky, ambient, sun, shadows, quality profiles, 3D resolution scale.
- Materials: one atlas texture per category (crops, ground, tractor), vertex colour as tint/AO.
- Foliage as alpha-scissor leaf cards (cheap, but alpha tests are costly on PowerVR, so keep
  the covered screen area small and test FPS on the Tecno phone before adding more).
- Texture import: project.godot importer defaults = VRAM compressed + mipmaps, so CI-built APKs
  stay small and use GPU-compressed textures.
- Not available in the Compatibility renderer: SSAO, volumetric fog, depth of field. We fake
  depth with baked vertex shading, blob shadows and optional sun shadows.
- Later: visibility_range distance culling, optional lower 3D resolution scale, MultiMesh
  batching of crops when fields grow (Milestone 4).

## 4. Phases (each is built, tested on the phone, then the next starts)

V1 Prep (no visible change): crop_data visual block, crop_stages.gd + tests, 4 stages,
   environment_setup.gd, assets/ folders, assets/LICENSES.md, budget file, CI size report.
V2 Texture pipeline: UV support in mesh_builder.gd, generated atlases (my Python tool),
   textured ground (soil, furrow, grass), importer defaults, alpha-scissor material.
V3 Crops: maize and beans, 4 stages each, textured leaf cards, cob/pod textures. I preview the
   meshes and textures as images before shipping. Then more crops by archetype, data only.
V4 World: tractor texture pass, textured house/trees/fence, sky and shadows tuned, LOD.

## 5. Asset sources

A. Generated by me (Python in my sandbox): stylised painted textures (leaf, soil, bark,
   kernels, metal) and UV-mapped meshes. Quality: good stylised mobile art, not photographs.
B. CC0 assets you download and upload to assets/ (ambientCG / Poly Haven textures, Kenney and
   Quaternius low-poly packs; always confirm the licence and record it in assets/LICENSES.md).
   I cannot download assets for you. GLB models are supported by Godot import in CI.
Recommended: start with A to prove the pipeline, swap in B where it looks better. The game
falls back to generated assets if a file is missing, so a bad upload never breaks the build.

## 6. Budgets (target: TECNO BF6 / Pop 7, 2-4 GB RAM, PowerVR GE8322)

- APK size: report in CI every build. Target to be set once we know the current size.
- Textures in the APK: 8 MB or less compressed. Atlases 512 or 1024 px, never larger.
- Visible triangles: 60k or less. Draw calls: 150 or less. Startup: 5 s or less.
- Crop mesh memory: 6 MB or less (build only crops in use, one variant at Low).
- FPS: Low stays near 50+ in drive view; Medium/High may be lower, shown in the menu.

## 7. Risks

- I cannot run Godot or see the game. Every step needs your screenshots and CI tests.
- Alpha-tested foliage and shadows may be too slow on this phone. Quality tiers protect us.
- First textured build may need a round of fixes (UV or import settings).
- Realism is bounded by asset quality. Generated textures are stylised.
